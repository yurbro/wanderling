# Wanderling 设计决策（设计的唯一依据）

更新：2026-10-06。来源：Cowork 里的两轮模拟工作室评审，原文见同目录的 `review-v1.md`、`review-v2.md`。

本文件是设计层面的唯一依据。做任何新功能之前先读它；代码、旧文档和它冲突时，以它为准。要改这里的内容，回到 Cowork 开一轮评审，不在 Code 会话里直接改设计。

## 1. 一句话

一个在路上给你写信的小旅人。场景负责此刻（和你窗外同一片天空），信件负责期待（他看到了什么，要等信）。

## 2. 五个产品支柱

1. 同一片天空：天空、天气、天象与用户的现实同步。
2. 他在路上：画面一直在，故事要等信。
3. 什么都不用做：可以参与，不参与也不会失去任何东西。
4. 小而可收藏：每张明信片都是能拿给别人看的一件小东西。
5. 总有一点意外：每次打开都可能遇见点什么，错过也不会失去。

每个新功能都要能说出它服务哪个支柱。违反第 3 条的直接否决：没有惩罚、没有「不打开就会失去」、没有连续天数。

v1 评审里已确认的规则：

- 信息节奏：他在哪随时知道，他看到了什么要等信。地标在场景里只是远远的剪影，完整的样子只在明信片上。
- 行囊：只有一格，物品不消耗，没有「行囊空了」的提醒。
- 不做天气面板。天气只以旅人的一句话出现；想看温度，点一下天空显示一个数字。
- 信里可以写他那边的真实天气，形成两地对照；场景天空始终是用户的。
- MVP 不推送；上架原生版后加每日最多一条的本地通知。
- 所有彩蛋错过了都不会消失，而是变成一封信。

## 5. 旅人设定（D1）

体型定稿（2026-10-06 Yu 选定）：C 团子的圆形身体，配 A 圆豆那样的背包，背包高度约为身体的 0.8 倍，大半藏在身体后面。参考图在 `docs/design/art/`：`character-wanderling-explore.png`（三种体型的生图，取右边的身体和左边的背包）、`character-wanderling-direction.png`（合成后的代码草图）。三视图 `character-wanderling-turnaround.png` 和动作表 `character-wanderling-poses.png` 已定稿；比例、每个动作的要点和不用照搬的地方见 `docs/design/art/README.md`。

外形：

- 身体：头身一体的圆团子（略呈蛋形，宽约为高的 0.9），米白色，略带纸感。
- 头顶一片小叶子：跟真实风向、风速摆动（`WorldState` 已有 `windSpeed`、`windDirection`）。叶子竖起是好奇，耷拉是困。
- 眼睛：两个墨点，可以睁、眨、弯成笑眼。没有嘴。
- 围巾：砖红 #B86B5A，尾巴随风飘，是全画面唯一的饱和焦点物。
- 背包：高度约为身体的 0.8 倍，颜色 #9C8A6A，以后挂行囊里的那件东西。
- 两条短腿，两只很小的手。画面里身高约为屏幕高度的 8%。
- 8 个可动部件：身体、叶子、眼睛、围巾尾、背包、两腿、双手。

动作状态：

| 状态 | 触发 | 表现 |
| --- | --- | --- |
| 走路 | 默认 | 身体起伏，叶子轻晃 |
| 撑伞 | 用户那边下雨 | 举起一片大叶子当伞（替换现在的靛蓝雨伞） |
| 提灯 | 日落后 | 手里一盏暖黄小灯（保留现在的灯笼与光晕） |
| 顶风 | 风速大于约 30 km/h | 身体前倾，叶子和围巾倒向一边 |
| 怕冷 | 气温低于 0°C | 围巾裹紧，偶尔呼出一口白气 |
| 睡觉 | 用户当地 2:00 到 4:00 | 蜷在路边，萤火虫彩蛋 |
| 张望 | 到达地标、路上的小事 | 停下，叶子竖起（保留现在的抬头看天、转头看镜头） |
| 挥手 | 长按他 | 回头挥手 |

性格：好奇、慢吞吞、有点迷糊，很认真地对待小事。他不完全懂人类的东西。他会想你，但从不怪你。

## 6. 文风与文案红线

- 第一人称，短句，每句不超过 12 个英文词。只写看到的、碰到的，不写道理。
- 把人类的东西说得稍微偏一点：雨伞是「会走的屋顶」，火车是「一座会跑的房子」。
- 除了一句天气关心，从不提醒用户做事；从不提用户多久没来。
- 禁用句式：「你错过了」「好久不见」「连续 X 天」，以及任何让人内疚的说法。
- 不在日常文案里出现使用时长、打开次数；出发天数只在里程碑信里用。
- 中文文案不用破折号「—」。

样句：

- Your sky was grey this morning. Mine too. I think the clouds are following me.
- I found a bench that faces the sea. I sat for a very long time. Benches are good.
- Rain tomorrow where you are. Bring your walking roof.

## 7. 与现有代码的合并方案

- 路线：保留现有的路线引擎、7 条短路线、接驳（走路、火车、飞机）和「在地图里选下一条」。离家最近的短路线就是「出门段」；D6 定下之后，长主线作为接下来的一段，经火车或飞机接入。
- 交通画面：现有的车窗和舷窗就是 v2 的 N1 车窗模式，已完成。
- HUD 底部的到站心情：升级为信件（明信片背面的话），由信件引擎生成。
- 节奏（D10）：把步速和歇息时长改到平均每站 2 到 3 天。注意引擎按时间戳推算进度，直接改常量会让已在路上的旅程倒退或跳站，改之前要先把当前里程存成新的起点。
- 明信片：保留现在的 SVG 小风景，并改为慢递（P3）：到站后按距离延迟几小时到两天送达，离用户的家越远越慢；送达前在收藏册里不出现，HUD 只说「他寄了一张明信片，在路上」。
- HUD 的「还有 X 公里」暂时保留，信件系统做好后再评要不要隐藏。
- 中文界面已完成，所有新文案都要走 `i18n.ts`。

## 8. 信件系统规格（MVP 史诗 B）

| 类型 | 频率 | 触发 |
| --- | --- | --- |
| 明信片 | 每 2 到 3 天 | 到站后按距离慢递，几小时到两天送达 |
| 路上的小事 | 每天至多 1 封 | 小事引擎抽取 |
| 天气关心 | 天气有变化时 | 明天用户那边有雨、雪或大风 |
| 天象信 | 每月几次 | 满月、流星雨、至日 |
| 错过信 | 彩蛋发生时用户不在 | 惊喜引擎 |
| 他会问你 | 每周 1 到 2 次 | 固定节点，用户点选项回答，下一封信会提到 |

节制规则：每天最多 2 封；同一天里明信片、天象信和错过信只留优先级最高的一封，其余顺延；信箱里未读最多 3 封，多的合并成一封「路上的几件事」，这样用户几天不来，回来也不会看到一堆未读。

实现规则：所有文本是「人写的骨架加实时变量」，MVP 不用 LLM 实时生成。变量：`{name}` `{place}` `{terrain}` `{hisWeather}` `{yourWeather}` `{yourTimeOfDay}` `{bagItem}` `{daysOnRoad}`。引擎记住已发过的骨架，不重复。文本放在数据文件里，入库前用脚本检查第 6 节的红线。

彩蛋同理写成数据规则：触发条件、概率、冷却时间、是否一次性、错过后的信件文案。演示模式要能强制触发任何一个彩蛋。
