Claude 的角色：架构、代码、单元测试、自动构建与部署、文档、内容生成与数据整理、图片后处理脚本、每次会话的进度记录。

## 2. 东西放在哪里

- 代码：GitHub 仓库，唯一真相。云端会话的工作目录每次都是新的，所以每次开工先拉代码，收工前推回去。没有推回去的代码等于不存在。
- 文档：这个 Project。产品定义、开发框架、本流程、风格指南、决策记录、开发日志、待办与停车场。
- 预览与构建产物：网页版自动部署到 GitHub Pages（免费、HTTPS），你在 iPhone 的 Safari 里打开即可；后期 iOS 原生包由云端 Mac 构建，经 TestFlight 装到手机。

仓库绑定（重要，2026-10-04 发现）：云端会话只能访问「启动会话时绑定为来源（sources）的仓库」。给 Claude 的 GitHub 授权是账号级的，不等于会话级绑定；未绑定的会话里，gh 与 git push 都会被代理拒绝，而且会话内没有添加仓库的工具。所以每次要推代码的会话，新建时都要把 yurbro/wanderling 加为来源。第一次代码上传走的是网页拖拽（见开发日志会话 3）。

## 3. 技术路线的调整（待你确认）

v1 框架推荐 Flutter。现在多了四个条件：iPhone、Windows、不装本机环境、先海外。在这些条件下我建议改走「网页优先」路线：

- 场景与 App 用 TypeScript 写，场景渲染用 PixiJS（WebGL 2D，粒子与滤镜很强），构建用 Vite。
- 第 1 到 2 阶段作为 PWA 使用：你在 iPhone Safari 打开网址，「添加到主屏幕」后就像一个 App，支持定位、全屏、推送通知（iOS 16.4 以上）。
- 第 3 阶段用 Capacitor 把同一套代码包成 iOS 原生应用上架 App Store，需要原生能力（HealthKit 步数、小组件、本地通知）时加插件或少量 Swift 代码，由云端 Mac 构建。

为什么改：你看效果的唯一渠道是 iPhone，而 Windows 不能构建 iOS。网页路线让你从第一周起就能在手机上看到每一次改动，不需要任何付费账号；我在云端也能直接渲染截图自检，不用每次安装大体积 SDK，迭代速度快得多；内测可以直接发链接，不经过 TestFlight。Flutter 仍然是可行方案（它也能出网页版），只是在这套约束下摩擦更大。两条路线的核心架构完全一样：WorldState 到 SceneDirector 到分层渲染，换路线不用重想设计。

已知代价与对策：
- iOS Safari 对普通网站的本地数据有「7 天未访问可能清理」的策略，添加到主屏幕的 PWA 不受此限，所以引导页要鼓励添加到主屏幕；MVP 阶段再加一个免费的云端备份（Supabase 或 Cloudflare），上架原生版后彻底解决。
- 网页里拿不到步数，步数加速放到原生版再做。
- 常驻 WebGL 动画比原生费电，对策是 30fps 封顶、页面不可见时暂停、粒子数封顶。

决策记录 ADR-001：技术路线改为网页优先（TypeScript + PixiJS + PWA，后期 Capacitor 包 iOS）。状态：Yu 于 2026-10-04 确认。

决策记录 ADR-002：代码的唯一真相是 GitHub 仓库 yurbro/wanderling；每次推送 main 自动测试、构建并部署到 GitHub Pages；Pages 的 Source 设为 GitHub Actions。状态：已实施（首个工作流随首次上传生效）。

## 4. 一次典型的开发会话

1. 你说一个小目标，一句话就够，例如「让旅人下雨时撑伞」，或者直接说「继续」。
2. 我读开发日志和待办，拉最新代码。
3. 实现，跑单元测试，在云端渲染截图自检。
4. 推送代码，自动部署，几分钟后预览网址更新；我把网址和「这次改了什么、看哪里」告诉你。
5. 你在 iPhone 上打开看，回一句话或一张截图。
6. 我更新开发日志、待办、决策记录。

节奏建议：一次会话一个目标，每周 2 到 4 次；大功能拆成多次；MVP 之外的新想法进「停车场」，不打断当前目标。你的反馈不需要专业，「这里太暗」「雨太大」「走路太快」就是最好的反馈。

## 5. 阶段与里程碑

时间按每周 2 到 3 次会话估算，忙的时候整体顺延即可，顺序不变。

### 阶段 0：搭台（第 1 周）

- 定名（见命名候选）。
- 你把 GitHub 连接到 Claude；我创建仓库、初始化工程、写 README。
- 配自动部署：每次推送自动构建并发布到 GitHub Pages。
- 你在 iPhone 上打开第一个「Hello」页面，添加到主屏幕，验证整条链路。
- Project 文档骨架：产品定义、风格指南、决策记录、开发日志、待办与停车场。

里程碑 M0：你手机主屏幕上有一个能打开的空壳。

### 阶段 1：魔法时刻原型（第 2 到 5 周）

- 第 2 周：WorldState 与 SceneDirector（纯逻辑，带单元测试）；太阳高度角与月相本地计算（用 suncalc 这类开源库）；天空色板随太阳高度变化；演示模式（拖动时间看一天的变化）。
- 第 3 周：接 Open-Meteo 天气（免费、无需 key），天气码映射到场景天气状态，缓存与离线降级；雨、雪、雾、云层用粒子和滤镜；浏览器定位，拒绝时手选城市（Open-Meteo 的地理编码接口也免费）。
- 第 4 周：旅人角色，先用代码绘制的矢量「纸偶」风格做走路循环；下雨撑伞、入夜提灯；视差滚动的路面与远山；夜晚路灯和窗灯。
- 第 5 周：质感打磨（手绘感线条、纸纹叠加、有限色板）；性能与电量；PWA 完整化（图标、启动画面、添加到主屏幕引导）；发给 3 到 5 个朋友，只问一个问题：第二天有没有再打开。

里程碑 M1：一个网址，打开就是和你窗外同步的天空，和一个一直在走的旅人。在这里决定是否继续。

### 阶段 2：MVP（第 6 到 17 周，约 3 个月）

六个史诗，每个 1 到 2 周，顺序可调：

- A 旅途引擎：路线图数据结构、时间驱动的进度、距离缩放、到达事件、本地持久化（IndexedDB）与云端备份。
- B 内容管线：地点表模板；首条路线 30 到 50 个地点（我出候选清单，你挑）；明信片文案由我在会话里直接写好英文初稿，你审校；校验脚本。
- C 美术管线：风格指南 v1；你先生成 3 到 5 张「风格锚点」图并确认；批量提示词模板；我写后处理脚本（去背景、统一色板、叠纸纹、按规格裁切）；资源清单与自动入库；逐步替换占位图。
- D 明信片与收藏：到达地标触发明信片；收藏册；足迹地图（风格化的手绘世界地图，走过的路线点亮）。
- E 角色：第二个角色，不同文风；基础装扮系统。
- F App 外壳：引导页（为什么要定位、如何添加到主屏幕）、设置（城市手选、通知频率）、中英双语、数据迁移。

然后 2 周内测：10 到 30 人，直接发链接。修 bug，收反馈。

里程碑 M2：可以给陌生人用的网页版。

### 阶段 3：上架 App Store（第 18 到 24 周）

- 你注册 Apple Developer（每年 99 美元）。
- 我用 Capacitor 生成 iOS 工程，配 Codemagic 或 GitHub Actions 的 macOS 跑道做云端构建（均有免费额度），先走 TestFlight 装到你的 iPhone。
- 原生能力：定位、本地通知、触感反馈；可选 HealthKit 步数加速。
- 上架材料：图标、启动图、截图（用演示模式截）、隐私政策页面（我写）、App Store 文案、隐私清单。
- 可选：同一套代码包安卓版上 Google Play（一次性 25 美元）。

里程碑 M3：App Store 上架。

### 阶段 4：陪伴深化与运营（上架后）

小组件与锁屏（需要少量 Swift，云端构建）、环境音、专注模式、LLM 个性化日记（一个小的 Cloudflare Worker 调用模型）、更多路线与角色、轻社交、变现（买断或内购，RevenueCat 之类的服务可省很多事）。每 2 到 4 周一个小版本。

## 6. 美术管线：AI 生图 + 你筛选

分工：静态图（明信片、地标、远景、道具）用 AI 生图；会动的旅人在原型期用代码矢量绘制，参考你选定的角色设计图配色，上线后若反响好再找人做正式的角色动画。原因是生图工具擅长单张静态插画，不擅长同一角色的连续动作帧。

工具建议：你已有 ChatGPT 账号，可直接用它的图像生成，上传风格锚点图作为参考能保持一致性；Recraft 可以直接输出矢量图（SVG），适合地标和道具，便于程序按昼夜重新上色，有免费额度；Midjourney 风格一致性最好但要付费。

流程：
1. 我写风格指南（线条、色板、留白、纸纹、构图规则）和提示词模板。
2. 你生成 3 到 5 张风格锚点图，我们一起定下「就是这个味道」。
3. 按资源清单批量生成，每个地点出 3 到 4 张，你挑 1 张。
4. 把选中的图上传到对话，我跑后处理脚本并入库，自动生成清单。
5. 所有图入库前过一遍风格指南的检查项。

## 8. 零经验者最容易卡住的地方与预案

1. 环境问题是最大的时间黑洞，所以本机什么都不装，构建与部署全在云端自动完成。
2. 代码没推回仓库就丢了：每次会话结束前我必须推送，并在开发日志里记录提交。
3. 看不懂报错：把截图或链接直接丢给我。
4. 需求膨胀：一次会话一个目标，新想法进停车场。
5. 美术风格不统一：先定风格锚点，再批量生成；入库前检查。
6. 会话之间失忆：开发日志是每次会话第一件读的、最后一件写的东西。
7. iOS 网页的数据清理：引导添加到主屏幕，MVP 加云端备份。
8. 你忙起来几周没动：没关系，所有状态都在仓库和 Project 里，回来说一句「继续」即可。
